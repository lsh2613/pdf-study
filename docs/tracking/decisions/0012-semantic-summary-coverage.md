# 요약 품질은 의미 coverage로 판정

> `content_map`의 important point를 먼저 선정하는 부분은
> [0015-section-first-summary.md](0015-section-first-summary.md)로 대체됐다.
> 고정 분량 대신 중요 누락·왜곡 검토를 쓰는 결정은 유지한다.

## 배경

기존 프롬프트는 번호형 서브 챕터를 Markdown 섹션으로 유지하도록 지시했지만,
저장 경계는 summary와 key points가 비어 있지 않은지만 확인했다. 따라서 원문이
충분히 전달됐는지, 명시적인 서브 챕터가 모두 포함됐는지와 무관하게 지나치게 짧은
요약도 완료될 수 있었다.

원문 글자 수나 페이지 수에 비례한 최소 분량은 문서마다 다른 정보 밀도와 전달
방식을 반영하지 못한다. 고정 글자 단위 분할도 문맥과 논리 흐름을 끊을 수 있다.

## 결정

- 챕터 원문은 임의 글자 수로 분할하지 않는다.
- 요약 전에 챕터 전체를 읽어 유의미한 내용을 `content_map`으로 기록한다.
- 명시적인 서브 챕터가 있으면 모든 서브 챕터를 원래 제목과 순서로 section에
  기록한다. 없으면 챕터 전체 section 하나에서 important point를 관리한다.
- 요약은 content map의 section과 important point를 의미 있게 반영한다.
- 별도 검토 단계가 원문, content map, 요약 초안을 대조한다. 중요한 누락이나
  왜곡이 있으면 `needs_revision`으로 보완한다.
- 서버는 모든 section·point coverage, 빈 누락·왜곡 목록, 명시적 서브 챕터
  heading의 Markdown 포함을 확인한 `passed` 결과만 완료로 저장한다.
- 요약 완료 판정에는 최소·최대 글자 수 또는 원문 대비 압축률을 사용하지 않는다.

## 대안

- 프롬프트에 “자세히 작성”만 추가: 모델별 해석 편차가 크고 저장 경계에서 누락을
  발견할 수 없어 채택하지 않았다.
- 원문 길이에 비례한 최소 요약 분량: 반복이 많은 문서와 정보 밀도가 높은 문서를
  같은 기준으로 다뤄 장황함 또는 누락을 만들 수 있어 채택하지 않았다.
- 고정 글자 수로 원문 분할: 서브 챕터와 논리 흐름을 끊을 수 있어 채택하지 않았다.

## 결과

요약 생성 호출은 content map 작성, 요약 초안, 독립 검토, 필요 시 수정 단계를
거친다. 최종 렌더러는 기존 summary와 key points를 그대로 사용하며 품질 증거는
재개·진단용 중립 데이터로 보존된다. 기존 클라이언트가 검토 증거 없이
`save_chapter_result`를 호출하면 완료되지 않고 누락 필드 오류를 받는다.
