# 기존 출력은 명시적으로 선택하고 관리 경로만 교체

## 배경

기본 출력 경로는 `result/<pdf_basename>`이어서 같은 PDF로 새 작업을 시작하면 기존
폴더를 다시 사용한다. 이전 구현은 새 `state.json`만 쓰고 raw·요약·문제 파일을
남겼으며, 렌더러도 이번 세대에 없는 챕터나 다른 출력 형식의 파일과 진도를 정리하지
않았다. 부분 렌더링에서는 현재 상태가 pending이어도 같은 챕터 ID의 예전 JSON을
읽을 수 있었다.

출력 폴더 전체를 비우면 혼재는 막을 수 있지만 사용자가 따로 둔 파일과 정상 진도를
함께 잃을 수 있다. 어떤 파일을 서버가 만들었는지와 새 학습 자료가 이전 진도와
호환되는지를 명시적으로 기록할 경계가 필요하다.

## 결정

- `init_work`는 기존 관리 작업이나 렌더 결과를 발견하면 자동 덮어쓰지 않는다.
- 재개 가능한 작업에는 `resume`, `replace`, `new_output_dir` 선택지를 반환한다.
  재개할 상태가 없으면 `replace`, `new_output_dir`만, 관리되지 않은 비어 있지 않은
  폴더에는 `new_output_dir`만 반환한다.
- `replace`는 사용자가 선택해 `replace_existing=true`를 전달한 경우에만 수행한다.
  새 PDF와 옵션을 먼저 검증하고 기존 `.work`만 제거한다. 이전 렌더 결과는 새 렌더가
  성공할 때까지 유지한다.
- 렌더러는 비어 있는 staging 폴더에 현재 세대를 완성한다.
- `.pdf-study-manifest.json`은 현재 형식, 학습 fingerprint, 서버가 관리하는
  top-level 경로를 기록한다. 설치는 이전 manifest의 관리 경로만 교체하며 실패하면
  이전 세대와 manifest를 복원한다.
- manifest 밖의 경로와 새 결과가 충돌하면 사용자 파일을 덮어쓰지 않고 실패한다.
- 진도는 이전 세대와 출력 형식 및 학습 fingerprint가 모두 같을 때만 복사한다.
- 중립 데이터 로더는 현재 상태가 `completed`인 요약·문제 파일만 읽는다.

## 대안

- 작업마다 고유 출력 폴더 사용: 삭제 위험은 작지만 결과 폴더가 계속 늘고 명시적
  `output_dir` 충돌 및 같은 작업의 재렌더 정리는 별도로 해결해야 한다.
- 출력 폴더 전체 삭제: 구현은 단순하지만 사용자 파일과 호환 가능한 진도까지 잃을
  수 있어 채택하지 않았다.

## 결과

같은 출력 폴더를 재사용해도 새 작업의 중간 데이터는 이전 작업과 섞이지 않는다.
형식 전환이나 챕터 감소 후에는 이전 세대의 관리 파일이 남지 않고, 동일한 학습물을
같은 형식으로 다시 렌더할 때만 진도가 유지된다. 사용자 파일은 manifest 소유권 밖에
있으며 같은 이름이 필요하면 자동 덮어쓰기 대신 명시적 오류가 발생한다.
