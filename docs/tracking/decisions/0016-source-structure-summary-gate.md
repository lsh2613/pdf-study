# raw 구조 대조로 요약 완료의 거짓 양성을 막는다

## 상태

부분 대체 — 2026-08-11 채택, raw 구조 저장 게이트는 0017로 대체됨

## 배경

section inventory와 의미 보존 review가 필수여도 생성 agent가 실제 원문을 충분히
읽지 않고 `has_explicit_subchapters=false`, 한 문장 요약, 형식만 맞춘 `passed`를
제출하면 서버는 JSON 형태만으로 이를 구분하지 못했다. 학습자 정보도 구조·요약
프롬프트에 함께 들어가 관심 분야와 겹치는 내용만 고르는 필터로 오해될 여지가 있었다.

## 결정

- 저장 시 canonical raw text에서 현재 챕터 번호와 일치하는 첫 줄 제목·반복 번호 제목,
  연속된 번호형 미니 목차와 이미 확인된 부모의 하위 번호를 보수적으로 찾는다.
- 확실히 찾은 모든 제목은 inventory에 있어야 하고 실제 제목·순서·번호 깊이와 parent
  관계를 유지해야 한다. 불일치는 review의 `passed`와 무관하게 거부한다.
- 챕터 제목에서 현재 번호를 확정할 수 없는 서문은 책 전체 목차 조각을 오인하지
  않도록 로컬 구조 검증을 생략한다. 번호 없는 제목과 OCR로 불규칙한 제목은 기존
  inventory 작성과 전체 원문 review가 담당한다.
- 이 로컬 검증은 챕터 경계를 만들지 않으며 요약 글자 수나 압축률을 평가하지 않는다.
- 분리 workflow의 학습자 정보는 inventory·요약·review 프롬프트에서 제거하고 기본·
  확장 문제의 난이도, 표현, 예시, 관점 조정에만 사용한다. 호환용 결합 프롬프트는
  요약 확정 뒤 문제 단계에서만 사용하도록 제한한다.
- agent가 보낸 `source_char_count`는 저장하지 않는다. raw의 값이 실제 text 길이와
  상태 값에 모두 일치하는지 확인한 뒤 교체한다.
- 챕터 설정 세대를 잠금 안에서 다시 확인해 검증 중 재설정된 챕터에 오래된 결과가
  저장되지 않게 한다.
- HTML과 Markdown+TUI에는 PDF 원문 복습을 위한 `학습용 요약`임을 명시한다.

## 결과

이번처럼 10만 자가 넘고 여러 단계 제목이 있는 원문을 “챕터 전체” 한 section과 한
문장으로 완료 처리하는 결과는 첫 누락 번호에서 거부된다. 길이 기준을 도입하지 않아
짧지만 의미상 완전한 문서는 계속 허용하며, 불규칙 구조는 모델의 원문 대조 책임으로
남는다.
