# 구조 inventory 뒤 section 전체를 직접 요약한다

## 상태

채택

## 배경

기존 흐름은 요약 전에 `content_map.sections[].important_points`를 만들고 이후 요약과
검토가 그 point coverage를 중심으로 동작했다. 이 목록은 의미 보존을 돕기 위한
장치였지만, 먼저 선택된 point가 사실상 요약 범위의 상한이 되어 목록 밖의 중요한
내용이 빠질 수 있었다. 또한 PDF마다 서브 챕터 표기와 계층 깊이가 다르고, 명시적인
서브 챕터가 전혀 없는 문서도 있다. 본문 속 “3장을 참고” 같은 교차 참조를 현재
챕터의 제목으로 잘못 인식할 위험도 있다.

## 결정

- 생성 순서는 `section inventory → summary → review → questions`로 한다.
- `section_inventory`는 실제 제목·순서·상대 계층만 기록한다. 요약할 내용이나 중요
  point를 미리 선정하지 않는다.
- 번호가 붙거나 붙지 않은 제목과 임의 깊이 계층을 허용한다. `level`은 현재 챕터
  안에서 1부터 시작하는 상대 깊이이고 `parent_id`는 가장 가까운 상위 section을
  가리킨다.
- 명시적인 서브 챕터가 있으면 모든 제목을 원래 순서와 계층대로 보존한다. 없으면
  `챕터 전체` section 하나만 만들며 원문에 없는 서브 챕터를 발명하지 않는다.
- 문장 속 다른 장의 단순 언급, 교차 참조, 목록 번호, 표·그림 번호, 페이지 머리말·
  꼬리말, 반복된 목차 조각은 현재 챕터의 section으로 만들지 않는다.
- 요약자는 inventory만 보고 내용을 고르지 않고 각 section의 원문 전체를 직접 읽어
  학습용 설명을 작성한다.
- 검토자는 원문·inventory·초안을 대조한다. inventory 자체의 구조 오류와 각
  section의 중요 누락·왜곡, 챕터 전체 흐름의 누락·왜곡을 확인한다. 모든 section과
  전체 검토가 `passed`인 결과만 저장한다.
- 서버는 챕터 길이나 구조에 따른 요약 분량을 정하지 않는다. 구조 판단과 설명
  충실도는 단계별 프롬프트 가이드와 독립 검토에 맡긴다.
- 공개 응답에는 `section_inventory_prompt`를 추가한다. 기존
  `content_map_prompt`는 같은 프롬프트를 반환하는 호환 alias로 유지한다.
- 구형 저장 payload의 `content_map`은 구조 정보만 `section_inventory`로 변환하고,
  `important_points`와 coverage id는 새 canonical 저장 데이터에서 제거한다.

## 결과

요약은 먼저 선택된 point에 갇히지 않고 원문 section 전체를 근거로 작성된다. 구조가
있는 문서는 원래 계층을 살리고, 구조가 없는 문서는 하나의 챕터로 유지한다. 서버가
PDF별 제목 패턴이나 긴 챕터 기준을 하드코딩하지 않으므로 특정 테스트 PDF에 종속되지
않는다. 대신 구조 inventory와 section별 검토 JSON이 저장 계약에 추가되며, 기존
클라이언트를 위한 제한적인 정규화 경로를 유지해야 한다.
