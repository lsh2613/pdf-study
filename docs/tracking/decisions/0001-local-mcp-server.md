# 로컬 MCP 서버 하나로 제공

## 배경

사용자는 로컬 PDF를 학습 자료로 바꾸려 한다. PDF 원문과 생성 결과는 사용자의 파일 시스템에 남고, MCP 클라이언트가 서버 도구를 순서대로 호출한다.

## 결정

하나의 로컬 MCP 서버가 작업 생성, PDF 스캔, 상태 저장, 검색 보조, 최종 렌더링을 모두 제공한다. 챕터별 요약과 문제 작성은 서버 내부 모델이 아니라 클라이언트 모델 또는 서브 에이전트가 맡는다.

## 대안

- 독립 CLI만 제공: 사람이 명령을 직접 조합해야 해서 MCP 클라이언트가 선택지와 다음 단계를 안정적으로 이어가기 어렵다.
- 원격 웹 서비스: 사용자 PDF와 결과물을 서버로 업로드해야 하며, 이 프로젝트의 로컬 학습 자료 생성 성격과 맞지 않는다.
- PDF 처리와 렌더링을 여러 서버로 분리: 현재 규모에서는 설정과 장애 지점이 늘고, 사용자가 등록해야 할 MCP가 많아진다.

## 결과

사용자는 MCP 서버 하나만 등록하면 된다. 서버는 원문 처리와 저장 계약을 강하게 통제하지만, 학습 내용 생성 품질은 클라이언트 모델의 지시 준수에 의존한다. 원격 다중 사용자 권한 모델은 현재 구조의 전제가 아니다.
