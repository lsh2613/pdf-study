# 새 작업의 학습자 정보 필수 입력

## 상태

채택 — 2026-08-04

## 배경

`init_work`의 학습자 정보 form은 선택 필드와 빈 문자열 기본값으로 정의돼 있었다.
그러나 Codex 클라이언트에서 입력 없이 제출하면 빈 문자열 승인 응답이 아니라
Elicitation 취소로 처리될 수 있어, 문서상 선택 입력인데도 실제로는 작업을 계속할 수
없는 불일치가 생겼다.

또한 객관식은 항상 활성화되고 기본·확장 문제 프롬프트가 학습자 정보로 난이도, 용어,
예시와 관점을 조정하므로 새 작업에서는 학습자 맥락을 명시적으로 확보하는 편이 제품
계약에 더 일관된다.

## 결정

- 새 `init_work(pdf_path)`는 단답형·주관식·확장형 form 뒤에 학습자 정보 form을
  항상 네 번째로 연다. 세 선택 유형을 모두 제외해도 생략하지 않는다.
- `user_context`는 `required`, `minLength=1`, default 없음인 MCP primitive string
  필드로 정의한다. 표시 제목에서 `(선택)`을 제거한다.
- 서버는 승인된 값을 trim하고 공백뿐인 입력을 거부한다. 모든 Elicitation과 검증이
  끝나기 전에는 작업을 만들거나 기존 관리 작업을 교체하지 않는다.
- 학습자 정보는 문제의 난이도, 용어 수준, 예시의 친숙도와 관점을 조정한다. 확장
  문제에서는 난이도와 현실·실무 맥락을 고르는 데 쓴다.
- 학습자 정보는 내용 근거가 아니다. 모든 기본·확장 문제는 계속 검토를 통과한 해당
  챕터의 `summary`와 `key_points`만 내용 근거로 사용한다.
- 공개 MCP 입력에 `user_context`나 선택 fallback을 추가하지 않는다. 입력은 form
  Elicitation 응답으로만 받는다.

## 호환성

- 기존 `.work/state.json`의 빈 `user_context`를 마이그레이션하거나 재개를 막지
  않는다.
- 기존 작업을 `resume_work` 또는 `init_work`의 이어가기로 여는 흐름에는 필수 form을
  추가하지 않는다.
- 이전 작업의 미정 문제 설정을 보완하는 `scan_pdf`는 기존 조건부 선택 입력과 빈
  문자열 허용을 유지한다.
- 이 결정은 `0007-extension-without-search.md`와
  `0009-request-context-and-elicitation.md`의 선택적 학습자 정보 결정 중 새 작업에
  해당하는 부분을 대체한다. 외부 검색 제거와 Elicitation-only 원칙은 유지한다.

## 결과

새 작업은 문제 생성 전에 사용할 학습자 맥락을 항상 갖는다. 빈 form 제출이
클라이언트별 취소 동작으로 바뀌는 모호함이 사라지고, schema와 서버 검증이 같은 필수
계약을 강제한다. 대신 사용자는 문제 유형 선택 뒤 학습자 정보를 한 번 더 반드시
입력해야 한다.
