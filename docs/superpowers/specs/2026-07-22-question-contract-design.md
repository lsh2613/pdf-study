# 문제 JSON 계약 단일화 설계

## 목표

요약·기본 문제와 확장 문제의 JSON 규격을 Python 내부 모듈 한 곳에서 관리한다.
프롬프트 예시, 서버 저장 검증, 테스트용 유효 payload가 같은 선언을 재사용하게 해
규격 변경 때의 불일치를 막는다.

## 범위와 비범위

- 새 내부 모듈은 문제 유형별 필수 문자열 필드, 객관식의 `options`·`answer_index`
  규칙, 유효 payload 예시를 제공한다.
- `server.py`는 모듈을 사용해 현행과 같은 성공·실패 기준과
  `data.missing` 필드 경로를 만든다.
- `prompts.py`와 테스트 fixture는 모듈이 제공하는 예시를 사용한다.
- MCP 도구명·입력 형식·응답 봉투·저장 JSON·상태 전환·`data.missing`의 경로 표기는
  바꾸지 않는다.
- JSON Schema·Pydantic·외부 검증 실행 파일·새 런타임 의존성은 추가하지 않는다.
- 문서는 사람이 읽는 계약 설명으로 유지하며, 문서 문자열 자체를 검증하는 테스트는
  사용자 결정에 따라 추가하지 않는다.

## 구성

`question_contract.py`는 기본 문제와 확장 문제의 규칙을 선언하고 다음 내부 API를
제공한다.

- 저장 payload의 누락·형식 오류 경로를 반환하는 검증 함수
- `prompts.py`가 JSON으로 넣을 기본·확장 문제 예시 생성 함수
- 테스트가 유효 payload를 만들 때 쓸 예시 생성 함수

`server.py`는 기존 저장 도구 경계에서 이 검증 함수만 호출한다. 저장 전 실패와
성공 후 상태·파일 기록의 순서는 현행을 유지한다. `prompts.py`는 템플릿의 JSON
블록을 예시 함수 결과로 채우며, 비활성 유형도 빈 배열 키를 유지한다.

## 검증

- 기존 저장 검증 테스트가 대표적인 잘못된 입력에서 동일한 `data.missing` 경로를
  반환하는지 확인한다.
- 기본·확장 프롬프트가 기존 필수 키와 예시를 포함하는지 확인한다.
- 렌더러 fixture와 서버 helper가 계약 모듈의 유효 payload를 사용해 기존 결과를
  유지하는지 확인한다.
- 전체 테스트를 실행해 외부 계약과 저장 동작의 회귀가 없는지 확인한다.
