# 새 init_work 학습자 정보 필수화 설계

## 목표

새 `init_work(pdf_path)` 작업은 문제 유형 선택 뒤 학습자 정보를 반드시 입력받는다.
빈 문자열이나 공백만 입력한 응답으로는 작업을 만들지 않는다. 이미 생성된 작업의
재개와 기존 `scan_pdf` 보완 흐름은 변경하지 않는다.

## 범위

- 새 `init_work`가 여는 학습자 정보 Elicitation을 필수 문자열 form으로 바꾼다.
- 단답형·주관식·확장형을 모두 제외해도 기본 객관식은 항상 활성화되므로 학습자
  정보 form을 연다.
- JSON Schema에서 `user_context`를 `required`로 만들고 `minLength=1`을 표시한다.
- 서버는 입력을 `strip()`한 뒤 빈 값이면 작업 생성 전에 실패한다.
- `docs/contracts.md`, `docs/business-rules.md`, 구조·상태 문서와 Elicitation 순서
  결정을 새 계약에 맞춘다.
- 학습자 정보가 기본 문제와 확장 문제 프롬프트에 실제로 포함되고, 난이도·용어
  수준·예시·문제 관점 조정에 쓰이도록 안내되는지 테스트로 고정한다.

## 비범위와 호환성

- 기존 `.work/state.json`의 빈 `user_context`를 마이그레이션하지 않는다.
- 기존 작업을 `resume_work` 또는 `init_work`의 `resume`으로 이어갈 때 새 입력을
  강제하지 않는다.
- 기존 작업의 미정 문제 설정을 보완하는 `scan_pdf` 경로는 이번 변경에서 필수화하지
  않는다.
- 공개 MCP 도구 입력에는 `user_context`나 선택 fallback을 추가하지 않는다.
- 요약·문제의 내용 근거 제한과 외부 검색 금지 규칙은 바꾸지 않는다.

## 동작과 데이터 흐름

1. `init_work`가 기존 출력 폴더 충돌을 확인한다.
2. 서버가 단답형, 주관식, 확장형 문제 생성 여부를 각각 form Elicitation으로 묻는다.
3. 세 선택과 무관하게 서버가 필수 `user_context` form을 연다.
4. Elicitation이 승인되지 않거나 입력을 정규화한 결과가 비어 있으면 작업과 출력
   상태를 만들지 않고 실패한다.
5. 유효한 학습자 정보와 문제 유형을 모두 받은 뒤에만 `workspace.create_workspace`를
   호출한다.
6. 저장된 `state.user_context`는 `prompts.build_prompts`에서 학습자 컨텍스트 블록으로
   변환되어 기본 문제와 선택적 확장 문제 프롬프트에 포함된다.

## 프롬프트 활용 계약

- 기본 문제는 검토를 통과한 `summary`와 `key_points`만 내용 근거로 사용한다.
  학습자 정보는 난이도, 용어 수준, 예시의 친숙도와 문제 관점을 조정하는 데만 쓴다.
- 확장 문제는 `summary`, `key_points`, 학습자 정보만으로 현실·실무 맥락과 난이도를
  조정한다. 외부 검색이나 원문 재참조는 허용하지 않는다.
- 의미 보존 `summary_review`에는 학습자 정보를 전달하지 않는다. 검토자는 학습자
  맞춤화가 아니라 원문·content map·요약 사이의 누락과 왜곡만 판정한다.

## 오류 처리

- 취소·거절은 기존과 같이 Elicitation 미승인 오류로 처리한다.
- 누락된 필드는 Pydantic form 검증에서 거부한다.
- 공백만 있는 문자열은 서버 정규화 검증에서 명시적으로 거부한다.
- 모든 실패는 출력 폴더 교체나 새 workspace 생성 전에 발생해야 한다.

## 테스트 설계

- 새 `init_work`의 네 번째 form이 `required=["user_context"]`, `minLength=1`이고
  선택 표시가 제거됐는지 확인한다.
- 선택 문제 유형을 모두 제외해도 학습자 정보 form이 열리는지 확인한다.
- 공백만 입력하면 실패하고 새 작업 폴더가 생기지 않는지 확인한다.
- 유효한 입력은 양끝 공백을 제거해 상태에 저장되는지 확인한다.
- FastMCP client/server 왕복에서 필수 스키마와 저장 결과를 검증한다.
- 기본 문제와 확장 문제 프롬프트 모두에 실제 학습자 정보와 활용 지침이 들어가는지
  검증한다.
- 관련 테스트 뒤 전체 테스트 스위트를 실행한다.
