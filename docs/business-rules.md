# 학습 자료 생성 규칙

## 사용자와 결과물

대상 사용자는 개발자로 한정하지 않는다. PDF 자체를 공부하거나 책을 PDF로 만들어 학습하려는 사람이 결과물을 바로 읽고 문제를 풀 수 있어야 한다. 따라서 결과물은 단순 요약 파일이 아니라 챕터별 요약, 핵심 포인트, 검증 문제, 선택적 확장 문제, 진도 저장을 갖춘 학습 자료여야 한다.

HTML 결과물은 비개발자도 결과 폴더에서 플랫폼별 실행 스크립트를 더블클릭해 열 수 있어야 한다. macOS/Linux의 `start_study.sh`와 Windows의 `start_study.bat`은 자료를 만든 같은 컴퓨터의 프로젝트 환경을 사용해 사용 가능한 포트를 자동 선택하고 loopback 서버와 브라우저를 연다. 진도는 계속 `progress/` 아래 JSON으로 저장하며, 직접 `study_html.py --port 8765`를 실행하는 호환 경로도 유지한다.

사용자가 PDF와 함께 학습, 요약본, 검증 문제, 퀴즈, HTML, TUI, study material 같은 의도를 보이면 일반 PDF 요약으로 끝내면 안 된다. 반드시 작업 생성, PDF 스캔, 챕터 확정, 챕터별 내용 생성, 누락 확인, 결과물 렌더링 순서로 처리해야 한다.

## 챕터 경계

챕터 경계의 정상 출처는 PDF 내장 목차와 목차 페이지 이미지뿐이다. 내장 목차가 있으면 그 PDF 페이지를 우선 후보로 삼고 사용자에게 확인한다. 내장 목차가 틀렸거나 없으면 `scan_pdf`가 목차 페이지 이미지를 렌더하고, 클라이언트는 `prepare_ocr` 후 `scan_toc_with_ocr`로 PaddleOCR CPU `ocr_text`를 받아 필요 시 이미지와 함께 확인해 챕터를 구성한다.

PDF 텍스트 레이어로 목차를 추정하면 안 된다. 스캔본, 깨진 글꼴, 발췌본에서는 텍스트의 줄 정렬과 페이지 번호가 믿을 수 없기 때문이다. 목차 이미지를 읽을 수 없을 때만 균등 청크나 직접 입력을 선택할 수 있다.

챕터 추출 범위는 항상 1-based inclusive `pdf_pages`로 저장한다. `source_pages`는 원문에 표시된 페이지 번호를 보존하는 선택적 표시 메타이며 추출 범위를 바꾸지 않는다. 사용자와 최종 결과에는 `PDF p.N–M · 원문 p.A–B`처럼 두 체계를 명시한다. 정상 텍스트 PDF는 텍스트 footer, 깨진 텍스트·스캔 PDF는 목차 이미지 OCR footer에서 반복 확인된 high 신뢰도 오프셋만 원문 페이지 계산에 쓴다. 단발·low 후보는 진단값일 뿐 `source_pages`를 만들지 않는다. 오프셋을 측정하지 못한 명시적 `source_pages=null`은 `원문 페이지 미상`, 오프셋을 아는 front matter는 `원문 페이지 없음`으로 표시한다. 사용자가 원문 페이지로 범위를 말하면 확인된 오프셋이 있을 때만 PDF 페이지로 변환한다.

색인, 찾아보기, 판권, 표지처럼 본문 학습 대상이 아닌 구간은 `skip` 처리한다. 건너뛴 챕터는 본문 추출, 요약 생성, 확장 문제 생성, 최종 렌더링 대상이 아니다. 본문 챕터를 건너뛰면 학습 자료가 빠진 것이므로 skip으로 표시하면 안 된다.

## 본문 추출 방식

text 모드는 PDF 텍스트 레이어를 신뢰할 수 있을 때만 쓴다. 텍스트 레이어가 없거나 모지바케로 깨진 PDF에서 text 모드를 쓰면 의미 없는 본문이 저장되므로 서버는 OCR 모드 선택을 요구해야 한다.

OCR이 필요한 목차 이미지 흐름 또는 텍스트 레이어가 없거나 깨진 PDF에서는
`prepare_ocr(work_id)`가 한국어·영어 OCR 언어 form elicitation을 직접 연다.
서버는 한국어와 영어만 OCR 대상으로 지원하며, 승인된 언어와 준비된 모델을 작업
상태에 보존한다.

`set_chapters`는 스캔 완료 여부, 처리 모드, 챕터 정의·범위·중복과 책 정보 fallback 준비를 상태 변경 없이 먼저 끝내야 한다. 이 검증이 실패하면 기존 모드, 챕터 진행 상태와 책 정보를 그대로 유지한다. 검증이 끝난 설정은 하나의 잠금 구간에서 `chapter_setup=completed`, `chapter_processing=in_progress`와 함께 확정한다. 그 뒤 본문 추출이 실패하면 설정을 되돌리지 않고 `chapter_processing=failed`와 챕터별 오류를 남겨 재시도 입력으로 사용한다. 모든 본문 챕터가 준비되면 처리 phase는 `completed`다. 같은 `work_id`의 다른 `set_chapters`는 setup부터 본문 준비와 phase 종결까지 앞선 호출이 끝난 뒤 시작해야 한다. state 저장 실패 뒤 책 정보 복원까지 실패하면 이를 숨기지 않고 transaction 실패로 드러낸다.

OCR 모드에서는 `set_chapters` 시점에 서버가 본문 챕터의 페이지 이미지를 PaddleOCR CPU로 읽어 `chapters_raw/chN.json`에 `text`와 `char_count`로 저장한다. 모델 캐시가 없으면 `set_chapters`는 본문 OCR을 시작하지 않고 `prepare_ocr`를 먼저 호출하게 해야 한다. 모델 캐시가 있으면 내부 모델 로드는 허용한다. skip 챕터는 OCR과 저장 대상에서 제외된다. 같은 `pdf_pages`의 유효한 OCR raw 본문이 이미 있으면 재OCR하지 않고 저장된 값을 재사용한다. OCR 선처리 병렬 상한은 서버 프로세스 전역으로 공유되며, 여러 호출이 겹쳐도 동시에 OCR되는 챕터 수는 최대 2개(CPU 1코어면 1개)를 넘지 않는다. 페이지 OCR 예외가 발생하거나 챕터 전체 OCR 결과가 공백이면 해당 챕터는 실패로 표시하고 partial raw 본문은 저장하지 않는다. 이 실패는 `set_chapters`와 `get_subagent_prompts`의 `failed_chapters`로 드러나며, 정상 sub-agent 흐름으로 넘어가면 안 된다. `get_subagent_prompts`와 `get_chapter_content`는 raw `text`와 `char_count`가 준비되지 않은 챕터를 거부한다. 요약 저장 payload에 `body_text`가 들어와도 raw 본문을 덮어쓰지 않는다.

처리 모드는 목차 분석 방식이 아니라 본문 입력과 챕터 처리 방식만 결정한다. 사용자가
text/OCR과 순차/병렬을 각각 고르기 전에는 서버가 기본값을 임의로 적용하면 안 된다.

사용자 선택값은 선택을 소비하는 도구가 실행 직전에 여는 MCP form elicitation
응답으로만 받는다. 공개 MCP 스키마에 선택 파라미터를 두거나 성공·실패 응답에
`choices`, `user_choice_required`, `user_choice_instruction` 같은 구조화 fallback을
제공하면 안 된다. 에이전트가 사용자를 대신해 선택값을 채울 수 있는 별도 경로도
두지 않는다. Elicitation 미지원 세션과 거절·취소는 상태와 출력 파일을 바꾸지 않고
실패해야 한다.

Elicitation form의 JSON Schema는 문자열·숫자·불리언과 지원되는 문자열 enum 같은
MCP primitive 필드만 사용한다. 새 `init_work`의 학습자 정보는 nullable union이나
빈 문자열 기본값이 아니라 `required`와 `minLength=1`을 가진 문자열 필드로 받는다.
서버도 trim 후 공백뿐인 값을 거부한다. 기존 작업의 미확정 설정을 보완하는
`scan_pdf` 흐름만 호환성을 위해 빈 문자열 기본값의 선택 입력을 유지한다. Form
최상위에는 클라이언트 계약 밖의 Pydantic 모델 메타데이터를 포함하지 않는다.

Form 필드 표시 문구는 내부 영문 키를 노출하지 않고 한국어로 작성한다. Codex가
다중 필드 form의 탐색 순서를 재배열할 수 있으므로 문제 유형은 각각 단일 필드
form으로 열어 `단답형 → 주관식 → 확장형` 호출 순서를 보장한다. 각 form은 먼저
읽을 설명을 `message`에, 짧은 항목명을 필드 `title`에 둔다. 선택지는 한글 이름으로 작성하고,
선택 결과를
이해하는 데 설명이 필요할 때만 같은 enum 항목에 짧게 덧붙인다. 의미가 자명한
선택지에 설명을 억지로 붙이지 않는다.
고유 형식명인 `html`, `md+tui`와 OCR 같은 약어는 예외로 유지할 수 있다.
Elicitation `message`에는 선택지 설명을 반복하지 않고 출력 위치, 실제 챕터 목록,
사용 가능 방식 제한, 삭제 위험처럼 그 단계에서 별도로 확인해야 하는 내용만 둔다.

선택이 필요한 각 워크플로는 form Elicitation과 승인 후 실행을 하나의 등록된 async
MCP 함수에서 처리한다. 동일 작업을 선택 인자로 직접 실행하는 별도 동기 함수,
`_impl` 함수, MCP wrapper를 두지 않는다. 테스트 준비는 선택형 워크플로 전체를
복제하지 않고 `workspace.py`·`analysis.py`의 하위 primitive만 사용한다.

`set_chapters`의 사용자 확인은 챕터 구성 방식, text/OCR 본문 추출 방식,
sequential/parallel 실행 방식으로 분리한다. 직접 입력을 고르면 PDF/원문 페이지
번호 기준과 `제목 | 시작-끝` 범위를, 균등 청크를 고르면 기본값이 표시된 청크당
PDF 페이지 수를 조건부 form으로 받는다. 표시된 챕터를 다시 확인하는 boolean은
두지 않는다. 두 처리 축은 독립된 결정이며 네 조합을 한 폼의 단일 선택지로 합치지
않는다. 앞선 요청이 거절·취소되면 뒤 요청과 상태 변경을 실행하지 않는다. 텍스트가
깨졌거나 없는 PDF의 추출 방식 폼은 OCR만 허용하고 그 이유를 message에 표시한다.

출력 폴더는 `server.py`가 위치한 MCP 서버 프로젝트 루트 아래
`result/<pdf_basename>`으로 계산한다. 공개 MCP 도구는 `output_dir`을 받지 않으며,
요청 workspace, MCP file root, 프로세스 cwd를 경로 계산에 사용하지 않는다.
`list_study_results`는 같은 고정 `result/*`의 직접 하위 디렉터리를 정렬된 절대
경로로 조회하며, 숨김 항목·파일·심볼릭 링크를 제외하고 상태를 변경하지 않는다.

공개 도구 설명, 오류와 `next_action`은 등록된 MCP 입력만 호출 예시에 사용할 수
있다. 선택은 해당 도구의 form Elicitation으로 받는다고 안내하고, 제거된 선택
파라미터나 번호형 자유 텍스트 선택지를 대체 경로로 제공하면 안 된다.

## 문제 생성

요약과 핵심 포인트는 모든 본문 챕터에 필요하다. 객관식은 기존 호환을 위해 기본
활성이다. 단답형, 주관식, 확장형은 기본값을 두지 않고 `init_work`가 여는 form
elicitation에서 사용자의 생성 여부를 받아 작업 생성 전에 확정한다. 작업 시작 때
켜진 유형만 요구하며 활성화된 기본 문제 유형이 비어 있으면 해당 챕터는 완료로 볼
수 없다.

새 `init_work`는 문제 유형 선택 뒤 학습 목적, 배경지식, 관심 분야, 현재 수준 같은
학습자 정보를 필수로 입력하게 한다. 단답형·주관식·확장형을 모두 제외해도 객관식이
활성화되므로 학습자 정보 form을 생략하지 않는다. 저장된 정보는 문제의 난이도,
용어 수준, 예시의 친숙도와 관점을 조정하는 데 실제로 사용한다. 확장 문제는 난이도와
현실·실무 맥락을 조정한다. 학습자 정보는 문제의 내용 근거가 아니며 검토를 통과한
`summary`와 `key_points`의 근거 제한보다 우선할 수 없다.

문제 개수 표는 목표치가 아니라 최대치다. 요약 근거가 부족하면 적게 만들어야 하며, 최대 개수를 채우려고 중복되거나 사소한 문제를 만들면 안 된다.

저장 시에도 챕터 본문 글자 수에 맞는 문제 유형별 최대 개수를 적용한다. 문제 ID는
영문자·숫자·`_`·`-`만 사용하며, 기본 문제와 확장 문제를 합친 한 챕터 안에서 중복될 수
없다. 이는 HTML의 문제 선택자와 HTML/TUI 진도 답안 키가 같은 문제를 안정적으로
가리키게 하기 위한 규칙이다.

| 챕터 글자 수 | 객관식 | 단답형 | 주관식 | 확장형 |
| --- | ---: | ---: | ---: | ---: |
| 3,000 미만 | 3 | 1 | 1 | 1 |
| 3,000 이상 10,000 미만 | 5 | 2 | 2 | 1 |
| 10,000 이상 25,000 미만 | 7 | 3 | 2 | 2 |
| 25,000 이상 | 10 | 4 | 3 | 3 |

기본 문제(객관식, 단답형, 주관식)는 의미 보존 검토를 통과한 현재 챕터의 `summary`와 `key_points`만으로 정답과 해설 또는 모범 답안을 유추하고 검증할 수 있어야 한다. 먼저 원문으로 내용 목록과 요약을 만들고 검토한 뒤, 별도 문제 생성 단계에는 원문과 content map을 전달하지 않는다. 외부 지식, 일반 상식, 다른 챕터 내용, 요약에 없는 원문 세부 정보가 있어야 풀 수 있는 문제는 만들면 안 된다. 주관식도 개인 의견형 토론이 아니라 요약 근거를 확인하는 검증형 문제여야 한다. 객관식에서 생성 agent는 정답 하나와 오답 보기를 만들고, 서버는 결과 저장 시에만 보기 순서와 정답 위치를 배치한다. 저장된 보기 순서와 정답 위치는 렌더·재개·재최종화에서 바뀌지 않는다.

요약은 Markdown으로 작성한다. 원문에 번호가 붙은 하위 절이 있으면 하위 절별 섹션을 유지한다. 이미지는 결과물에 삽입하지 않고, 필요한 그림 내용은 글이나 표로 풀어 설명한다.

요약 품질은 원문 글자 수나 고정 압축률로 판단하지 않는다. 책·보고서·교재·서사 등
문서마다 의미를 전달하는 방식과 정보 밀도가 다르기 때문이다. 요약자는 먼저 챕터
본문 전체를 읽고, 최종 요약에서 빠뜨리면 의미 전달이 손상되는 내용을
`content_map`으로 정리한다. 명시적인 서브 챕터가 있으면 모든 서브 챕터를 원래
순서와 제목으로 각각 기록하고, 없으면 챕터 전체를 하나의 source section으로
분석한다. 핵심 주장·개념·관계·절차·조건·예외·비교·근거·사례·주의점 가운데
실제 원문에서 유의미한 요소를 문서 성격에 맞게 보존한다.

요약 초안은 별도 검토 단계에서 챕터 본문 전체와 `content_map`에 대조한다.
명시적인 서브 챕터는 최종 Markdown에 제목이 직접 나타나야 하고, 모든 section과
important point가 의미 있게 반영돼야 한다. 중요한 누락이나 왜곡이 있으면
`needs_revision`으로 보완하며, 누락·왜곡이 없고 전체 content id coverage가 확인된
`passed` 검토만 저장할 수 있다. 특정 글자 수를 채우거나 원문 대비 비율을 맞추는
것은 통과 기준이 아니다.

최종 학습 자료에는 PDF 이미지가 포함되지 않는다. 따라서 그림, 도표, 이미지의 시각 정보에 의존하는 기본 문제는 만들면 안 된다. 그림 설명이나 캡션이 요약에 포함되더라도 그 요약 텍스트만으로 충분히 답할 수 있을 때만 문제화한다.

확장 문제는 요약 학습을 넓히기 위한 보조 유형이다. 단순히 요약 문장을 다시 묻는 문제가 아니라 요약의 핵심 개념을 현실 맥락, 실무 적용, 경험 기반 판단 상황, 사회적·기술적 이슈와 연결하는 응용 문제여야 한다. 꼭 하나의 정답으로 닫히지 않는 사고형 문제도 허용하지만, 학습자가 비교할 수 있는 모범 답안은 반드시 포함해야 한다.

확장 문제는 외부 검색이나 별도 자료 수집 없이 저장된 해당 챕터의 `summary`, `key_points`와 학습자 정보만으로 만든다. `get_chapter_summary`는 문제 생성에 원문을 다시 전달하지 않으며, 원문 글자 수는 문제 개수 상한 계산에만 사용한다. 현실·실무 맥락이 필요하면 문제 안에 필요한 상황과 조건을 충분히 제시해 스스로 완결되게 만들며, 최신 외부 사실이나 별도 출처를 알아야만 답할 수 있는 문제는 만들지 않는다.

## 완료 판정

챕터 요약 저장은 요약, 핵심 포인트, 활성 기본 문제 유형, 유효한 `content_map`,
`passed` 상태의 `summary_review`가 모두 준비됐을 때만 완료다. 검토는 content map의
모든 section·important point를 coverage에 포함하고, 중요한 누락·왜곡 배열이 비어
있어야 한다. 확장 문제 저장은 `questions.extension`이 비어 있지 않을 때만 완료다.

최종 렌더링은 완료된 결과만 자료에 넣는다. 미완료 결과가 있어도 완료분 자료를 만들되,
응답에서 미반영 챕터와 결과 종류·상태·오류를 반드시 알린다. `pending`, `in_progress`,
`failed` 결과는 완료로 표시하거나 예전 파일을 포함하면 안 된다.

작업 재개는 `<output_dir>/.work/state.json`의 상태를 기준으로 한다. 서버 프로세스가 재시작되어 메모리 등록이 사라져도 디스크 상태가 남아 있으면 같은 `work_id`로 남은 챕터만 이어서 처리할 수 있어야 한다.

재개 시 `get_subagent_prompts`는 챕터 설정이 완료된 작업에서만 완료되지 않은 결과를 `summary_pending_chapter_ids`와 `extension_pending_chapter_ids`로 나눠 반환한다. 호환용 `chapter_ids`는 두 목록의 자연 정렬 합집합이다. raw 검증은 summary pending에만 적용하고, extension-only pending은 저장 요약을 검증한다. workflow와 `next_action`은 각 챕터에 실제로 남은 요약 또는 확장 결과만 생성·저장하도록 안내해야 한다. 두 목록이 모두 비면 이 도구는 `finalize_study`를 직접 안내하지 않고 `list_pending_chapters`를 먼저 호출하게 해야 한다.

챕터 설정이 완료되고 두 pending 목록이 비면 `list_pending_chapters`와 `resume_work`는
선택 파라미터 없는 `finalize_study`를 다음 도구로 반환한다. 해당 도구가
`html`/`md_tui` form elicitation을 직접 열며 서버가 출력 형식을 기본 적용하면 안 된다.

최종 렌더가 완료된 뒤 중간 데이터 제거를 원하면 `cleanup_work`가 그 작업의 `.work`만
삭제한다. 이 동작은 렌더·진도 설치를 다시 수행하지 않으며, 렌더가 완료되지 않은
작업은 재개 가능성을 보호하기 위해 삭제할 수 없다.

## 출력 폴더 재사용

기존 작업이나 렌더 결과가 있는 출력 폴더는 새 작업이 자동으로 덮어쓰면 안 된다.
재개 가능한 작업은 이어가기 또는 기존 작업 교체를 사용자가 명시적으로 선택한다.
재개할 상태가 없는 완료 결과는 교체를 승인해야 새 작업을 만들 수 있다.
pdf-learner가 관리하지 않는 파일이 있는 고정 출력 폴더는 사용하지 않고 실패한다.

교체를 선택해도 새 입력 검증이 끝나기 전에는 기존 `.work`를 제거하지 않는다. 기존 렌더 결과는 새 렌더가 완전히 성공할 때까지 유지한다. 새 세대 설치 시 서버가 지울 수 있는 범위는 이전 `.pdf-learner-manifest.json`의 관리 경로뿐이며 다른 사용자 파일과 충돌하면 렌더링을 실패시킨다.

학습 진도는 같은 출력 형식과 같은 학습 fingerprint에서만 유지한다. PDF 식별 정보, 챕터 구성, 문제 유형, 책 정보, 요약 또는 문제가 달라지면 이전 답안과 완료 상태를 새 자료에 적용하지 않는다.
