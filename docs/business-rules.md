# 학습 자료 생성 규칙

## 사용자와 결과물

대상 사용자는 개발자로 한정하지 않는다. PDF 자체를 공부하거나 책을 PDF로 만들어 학습하려는 사람이 결과물을 바로 읽고 문제를 풀 수 있어야 한다. 따라서 결과물은 단순 요약 파일이 아니라 챕터별 요약, 핵심 포인트, 검증 문제, 선택적 확장 문제, 진도 저장을 갖춘 학습 자료여야 한다.

사용자가 PDF와 함께 학습, 요약본, 검증 문제, 퀴즈, HTML, TUI, study material 같은 의도를 보이면 일반 PDF 요약으로 끝내면 안 된다. 반드시 작업 생성, PDF 스캔, 챕터 확정, 챕터별 내용 생성, 누락 확인, 결과물 렌더링 순서로 처리해야 한다.

## 챕터 경계

챕터 경계의 정상 출처는 PDF 내장 목차와 목차 페이지 이미지뿐이다. 내장 목차가 있으면 그 물리 페이지를 우선 후보로 삼고 사용자에게 확인한다. 내장 목차가 틀렸거나 없으면 목차 페이지 이미지를 사람이 읽듯 해석해 챕터를 구성한다.

PDF 텍스트 레이어로 목차를 추정하면 안 된다. 스캔본, 깨진 글꼴, 발췌본에서는 텍스트의 줄 정렬과 페이지 번호가 믿을 수 없기 때문이다. 목차 이미지를 읽을 수 없을 때만 균등 청크나 직접 입력을 선택할 수 있다.

챕터 범위는 항상 PDF의 물리 페이지 번호로 저장한다. 사용자에게는 가능하면 PDF 페이지와 책 페이지를 함께 보여주지만, 서버 입력의 기준은 물리 페이지다. 사용자가 책 페이지로 범위를 말하면 확인된 오프셋이 있을 때만 물리 페이지로 변환한다.

색인, 찾아보기, 판권, 표지처럼 본문 학습 대상이 아닌 구간은 `skip` 처리한다. 건너뛴 챕터는 본문 추출, 요약 생성, 확장 문제 생성, 최종 렌더링 대상이 아니다. 본문 챕터를 건너뛰면 학습 자료가 빠진 것이므로 skip으로 표시하면 안 된다.

## 본문 추출 방식

text 모드는 PDF 텍스트 레이어를 신뢰할 수 있을 때만 쓴다. 텍스트 레이어가 없거나 모지바케로 깨진 PDF에서 text 모드를 쓰면 의미 없는 본문이 저장되므로 서버는 OCR 모드 선택을 요구해야 한다.

OCR 모드에서는 서버가 본문 문자열을 만들지 않는다. 서버는 챕터 페이지 이미지를 제공하고, 요약자가 이미지를 순서대로 읽어 본문을 파악한다. OCR 모드의 요약자는 읽어낸 전체 본문을 `body_text`로 함께 제출해야 하며, 서버는 그 값이 있을 때 원문 저장소에 되돌려 넣어 이후 렌더링과 진단에서 text 모드와 같은 형태로 다룬다. 저장 경계가 `body_text` 누락을 직접 거부하는 검증은 아직 남아 있다.

처리 모드는 목차 분석 방식이 아니라 본문 입력과 챕터 처리 방식만 결정한다. 사용자가 text/OCR과 순차/병렬 조합을 고르기 전에는 서버가 기본값을 임의로 적용하면 안 된다.

## 문제 생성

요약과 핵심 포인트는 모든 본문 챕터에 필요하다. 객관식, 단답형, 주관식, 확장형은 작업 시작 때 켜진 유형만 요구한다. 활성화된 기본 문제 유형이 비어 있으면 해당 챕터는 완료로 볼 수 없다.

문제 개수 표는 목표치가 아니라 최대치다. 본문 근거가 부족하면 적게 만들어야 하며, 최대 개수를 채우려고 중복되거나 사소한 문제를 만들면 안 된다.

요약은 Markdown으로 작성한다. 원문에 번호가 붙은 하위 절이 있으면 하위 절별 섹션을 유지한다. 이미지는 결과물에 삽입하지 않고, 필요한 그림 내용은 글이나 표로 풀어 설명한다.

확장 문제는 본문 학습을 넓히기 위한 보조 유형이다. 외부 검색 결과가 있으면 출처 URL을 보존하고, 검색이 실패하거나 결과가 없으면 본문 지식만으로 확장 문제를 만들며 출처 목록은 비워 둔다.

## 완료 판정

챕터 요약 저장은 요약, 핵심 포인트, 활성 기본 문제 유형이 모두 비어 있지 않을 때만 완료다. 확장 문제 저장은 `questions.extension`이 비어 있지 않을 때만 완료다.

최종 렌더링은 처리되지 않은 챕터가 남아 있으면 기본적으로 실패해야 한다. 사용자가 부분 결과를 명시적으로 원할 때만 강제 렌더링을 허용한다.

작업 재개는 `<output_dir>/.work/state.json`의 상태를 기준으로 한다. 서버 프로세스가 재시작되어 메모리 등록이 사라져도 디스크 상태가 남아 있으면 같은 `work_id`로 남은 챕터만 이어서 처리할 수 있어야 한다.
