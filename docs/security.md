# 보안 기준

## 보호 대상

사용자가 제공한 PDF, 추출된 원문, OCR로 읽은 본문, 요약·문제 JSON, 최종 HTML/TUI 결과물은 사용자 로컬 자료다. pdf-study 서버가 맡는 PDF 처리, 상태 저장, 확장 문제 지원, 렌더링은 로컬 파일 시스템 안에서 끝나야 하며 서버가 본문이나 생성 결과를 외부 검색·HTTP API로 보내면 안 된다.

현재 프로젝트에는 계정, 로그인, 원격 사용자 권한 모델이 없다. 서버는 MCP 클라이언트가 실행한 로컬 프로세스로 동작하며, 접근 권한은 해당 OS 사용자 권한에 따른다. 여러 사용자를 분리하는 서버로 바꾸는 변경은 보호 대상과 접근 규칙을 새로 정해야 한다.

## 네트워크 경계

확장 문제는 외부 검색 없이 챕터 본문과 사용자가 제공한 학습자 정보만으로 만든다. 서버는 외부 검색 도구나 검색용 HTTP 클라이언트를 제공하지 않는다. 확장 문제를 위해 검색 결과, URL, 외부 자료 요약을 저장하는 스키마도 두지 않는다.

MCP 클라이언트가 챕터 본문을 어떤 모델 실행 환경으로 전달하는지는 해당 클라이언트와 모델 제공자의 경계다. pdf-study 서버 문서가 그 전송을 로컬 처리라고 보장해서는 안 된다. 서버에 새로운 외부 통신을 추가하려면 전송 대상, 동의 방식, 실패 정책을 별도 결정으로 먼저 기록해야 한다.

## 파일 접근

`init_work`는 사용자가 지정한 PDF 경로가 실제 존재할 때만 작업을 만든다. 존재하지 않는 파일을 임의로 생성하거나 다른 경로로 대체하면 안 된다.

결과 폴더의 `.work/`에는 원문과 중간 결과가 들어간다. 이 폴더를 공개 저장소에 올리면 PDF 본문이나 사용자의 학습 결과가 노출될 수 있으므로 커밋 대상에서 제외해야 한다.

기존 출력 폴더를 교체할 때는 사용자의 명시적 선택과 새 입력 검증이 먼저 끝나야 한다. 중간 작업 교체는 정확한 `<output_dir>/.work`만 대상으로 하고, 렌더 결과 교체는 유효한 `.pdf-study-manifest.json`의 관리 경로로 제한한다. manifest 밖의 사용자 파일과 이름이 충돌하면 덮어쓰거나 삭제하지 않고 실패해야 한다.

공개 MCP 도구는 `output_dir`을 받지 않는다. 요청의 단일 Codex workspace 또는 단일
MCP file root 아래 `result/<pdf-name>`으로만 출력 경로를 계산한다. MCP 서버
프로세스 cwd를 대체 경로로 쓰거나 여러 workspace 중 하나를 임의 선택하면 다른
프로젝트의 파일을 대상으로 삼을 수 있으므로, 모호한 경우 상태 변경 없이 실패한다.
기존 관리 작업의 재개·교체는 form elicitation으로 확인하고, 거절·취소 시 파일을
바꾸지 않는다. 관리되지 않은 파일이 있는 고정 출력 폴더는 덮어쓰지 않는다.

사용자 선택 파라미터와 구조화 fallback은 공개 MCP 계약에 두지 않는다. 이를
추가하면 에이전트가 Elicitation을 우회해 교체·정리 같은 상태 변경을 시도할 수 있다.

HTML 결과물의 진도 저장 서버는 생성된 결과 폴더 안의 progress API와 정적 파일 제공에 한정된다. 임의 파일 읽기, 상위 경로 접근, 안전하지 않은 progress 이름은 거부해야 한다.

## 실패 경로

PDF를 열 수 없거나 챕터 범위가 문서 밖이면 작업을 계속하면 안 된다. 오류 응답으로 멈추고, 클라이언트가 사용자에게 수정된 입력을 받게 해야 한다.

필수 요약·문제 필드가 비어 있으면 완료 상태로 저장하면 안 된다. 빈 결과를 완료로 표시하면 사용자는 최종 자료가 완성됐다고 믿게 되고, 이후 재시도 기회도 사라진다.

서버가 알 수 없는 `work_id`를 받으면 임의 폴더를 추측하지 않는다. 재개는
`resume_work(pdf_path)`가 단일 요청 workspace의 고정 경로에서만 수행한다.
